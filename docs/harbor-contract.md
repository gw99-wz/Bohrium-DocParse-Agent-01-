# Harbor 运行契约（从官方题面摘录整理）

来源：赛题页 `product-arena-08-3027d350` 的「Harbor技术提交约定」，原文见 [challenge.md](challenge.md)。

## 提交结构

| 位置 | 内容 |
|---|---|
| `/app/submission/SKILL.md` | Skill 本体，必须带合法的 `name` / `description` YAML frontmatter |
| `/app/submission/**` | 实际使用的提示、规则、脚本、配置、模板、词表等文本资源 |
| 根路径 `GITHUB_URL.txt` | 第一行写作品 GitHub 链接；可选第二行写提交目录内相对路径 |

## 评测方式

1. 评测方把参赛 Skill 安装到 `/skills/weekly-skill`。
2. 在官方 DeepSeek Harness 上对每个固定原始案例运行：基础 Agent 与 Skill Agent 各 3 次（3 案例 × 3 次对照）。
3. 正式案例由平台提供，参赛者不提交预置答案、隐藏测试或白板。

## 运行时输入 / 输出

| 项目 | 约定 |
|---|---|
| 输入 | `/input/case.json` 与 `task.md`；PDF 直接给原始文件，**没有**预抽取答案层 |
| 工作目录 | `/app/work` |
| 输出 | `/app/output`：`result.json` 需包含原始 output_contract 的全部字段 + `case_id` |
| 结果质量 | 必须如实记录 status、sources、uncertainty、change records；不得伪造缺失软件状态或科学数据 |
| 可视化交付 | 可编辑 Office / 幻灯片 / 图表输出需同时给出真实渲染的 PDF/PNG 预览 |
| 部分完成 | 必须标明边界，不得把「无法判断」写成事实 |

## 预算与限制

- 执行预算：**64 次模型请求**、**900 秒**、**每次响应 16384 tokens**（含推理）。
- 应尽早保存诚实的部分交付物，再逐步改进。
- 实际服务故障单独暂停处理。
- Skill 资源：最多 **50 个 UTF-8 文本文件**，单文件 ≤ **500KB**，总计 ≤ **2MB**，**不允许符号链接**。
- 运行时产物可以是二进制，独立于最终 JSON 有效性保留。

## 资源入口

- `environment/resources.yaml` 为资源入口；随附文件相对于该目录。
- 声明的预装运行时路径描述固定镜像；真实固定案例由评测平台提供。

## 评分重心（原题 100 分 + GitHub 5 分）

- 实际效果 40：完成度 15 / 正确性 15 / 完整性 5 / 可核验性 5
- 使用增益 25：质量增益 15 / 效率增益 5 / 增益可验证性 5
- 创新增益 15：新增能力 5 / 方法改进 5 / 创新证据 5
- 可靠体验 10：调用与易用性 3 / 运行稳定性 4 / 异常处理 3
- 生态贡献 10：文档完整性 3 / 资源可复用性 4 / 分享推广价值 3
- GitHub 公开作品链接 +5：评审无需登录可打开并找到作品

## 对照条件

基础 Agent 与 Skill Agent 使用相同案例输入、任务要求和可比条件；平台预置白板（whiteboard）作为对照结果，不是参赛者答案。
